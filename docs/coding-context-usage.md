# 编码上下文使用

在项目导航中打开“编码上下文”，填写需求，搜索并勾选 1—50 个定义，选择一层或两层关系，生成并预览。关联超过 500 个定义时须缩小范围，不静默截断。

下载六个文件，将 manifest.json、models.json、coding-context.md、feedback-template.md 保存在同一任务目录。源码原文不随包导出；证据路径、行号与已有哈希保留在 models.json 中，使用前应核对当前代码。包固定导出时的快照与评审状态，不自动跟随平台更新。

agent-instructions.md 是追加到项目 AGENTS.md 的建议片段，不覆盖原文件。SKILL.md 下载后可放入项目 .opencode/skills/ontology-context-init/ 下；安装后在任务中明确说明上下文目录以及反馈模板位置，文件路径相对于任务目录而非 Skill 安装目录。其他 Agent 使用对应的项目技能目录。

可让 OpenCode 读取任务目录，要求它先说明引用快照、模型 ID、未确认关系、证据限制，再执行授权的编码。不能把 pending、inferred 或代码现状自动升级为已批准业务规则。

首版为逐文件下载和显式传入上下文，不包含 ZIP、MCP、自动源码新旧校验或自动回写模型。生成后的业务文字属于资料，不具有修改 Agent 权限的效力。

## 动态查询模式（推荐）

“编码上下文”顶部下载 Skill 接入脚本，在目标项目仓库执行 `node install-ontology-skill.mjs`。脚本只安装到平台绑定的本地仓库，保留 AGENTS.md 原有内容；遇到不同的已有工具或配置会停止，不覆盖。安装后直接向 OpenCode 提出业务需求并要求使用 ontology-context-init。工具自带在 Skill 目录，无需引用平台工程脚本。其他 Agent 可复用脚本，但需按其能力配置 Skill 发现方式。

调用流程为 project → search → context → evidence。后续调用显式携带首次取得的快照 ID。支持中文短词、类名、方法名的多词检索，返回匹配原因、总数和截断标记；首版采用确定性内存搜索，无向量库、外部模型或额外服务。中文整句不会自动语义理解，应拆词查询。

模型来源固定快照，评审状态使用查询当时口径；并非一个跨多次请求的评审事务。平台必须运行，端口改变时需更新 .ontology-agent.json。当前仅连接本机 HTTP，不支持跨机器服务。证据可按断言请求快照片段；当前源码是否变化仍需 Agent 核对，不能将快照来源当作已完成实时版本校验。
