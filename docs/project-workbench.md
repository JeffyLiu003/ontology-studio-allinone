# 项目建模工作台

本轮扩展复用现有七／十一模型、源码证据、独立评审、语义层、AI分析和编码上下文。入口：选择建模方法与项目后打开「项目建模工作台」（`/#/workbench`）。新功能不自动重新分析历史项目，不替用户确认或发布已有业务知识。

## 八项能力与操作

| 能力 | 入口及行为 |
|---|---|
| MI接口／MM映射 | 十一模型项目增量分析后进入「模型目录」；Spring REST提取方法参数、绑定、必填声明和返回类型，JPA提取显式表名／列名，保留来源证据 |
| 结构化编辑 | 「结构化本体编辑」选择已有模型或新建；编辑字段、引用、参数、对象属性、流程活动及表列映射，校验后生成新草稿快照 |
| 多类资料 | 「项目资料与增量任务」加入源码目录、文档目录或上传补充文档；上传后默认自动进行本地增量分析，可取消勾选 |
| 一致性校验 | 「一致性与差异」检查悬空／类型引用、查询双向绑定、流程循环等，记录空模型的未知／待建模／不适用及依据 |
| 增量影响 | 按资料内容、建模方法、分析器版本校验缓存；未变成功单元复用、变更单元重算，新快照列出模型差异和需要重新核验的人工修订 |
| 关系探索 | 「关系探索」从业务对象、接口、事件等元素出发，沿已有关系展开1–3层，可选100／300／1000／2000节点，保留拖拽、缩放和证据详情 |
| 失败恢复 | 查看资料单元状态和错误；失败不切换当前项目快照，其他资料仍继续；修复后点「增量分析／恢复失败单元」复用成功检查点，支持取消 |
| 基线与反馈 | 「确认基线」提交、人工评审后发布冻结版本、导出上下文；「编码反馈」接收实现摘要、文件和测试声明，经核验后应用建议生成新草稿 |

## 推荐使用顺序

1. 选择七模型 · v9 或十一模型 · v6，再选择项目。两种方法的项目分别管理。
2. 加入项目资料；原代码工程中已有知识文档时，可将其知识子目录作为补充文档资料加入同一项目。当前不是上传代码包后自动对所有文件完成双通道发现。
3. 启动增量分析，查看各资料单元。全部成功后生成新快照；失败修复后重新启动即可恢复。原「重新分析」仍是原有单资料全量入口。
4. 编辑模型、检查差异、复核源码与文档。默认代码候选优先呈现当前实现，文档要求保留；同名提示不会自动合并或删除任何定义。
5. 在模型详情与业务语义界面分别确认定义和关系。没有证据的草稿不能发布。空模型须明确说明不适用，不能把缺失直接视为已完成。
6. 提交并发布确认基线。若已有新快照，旧的待评审提交不能发布；重新提交当前版本。已发布内容冻结，后续草稿不改变它。
7. 编码 Agent 固定已发布基线或明确快照查询，返回反馈。核验反馈后可应用字段修订，但不自动确认、发布或执行目标仓库代码。

## 已实现的校验范围

共享字段描述约束允许修改的字段、类型与枚举；后端禁止篡改节点ID、模型类型、来源上下文和证据锚点。引用必须指向本快照中符合类型的定义。复杂条件、节点图等字段仍保留结构化JSON编辑，不代表任意可视化流程设计器。

跨模型检查包括重复ID、空名称、重复对象属性、引用类型及存在性、M7与M2 QUERY双向绑定、M4混入人工审批／网关／子流程、M6子流程循环、M5角色继承循环、MU事件发布前的生产行为等。校验结果同时接入「覆盖与质量」及现有AI问题分析入口。这些是关键静态约束，不是完整v6／v9形式化验证或业务准确性证明。

## 检查点和证据策略

- 检查点粒度为资料目录／一次文档上传组成的资料单元；单元内文件变动会重算该单元，尚无逐文件解析阶段断点。
- 缓存同时核验输出JSON、源映射及隔离源文件；损坏缓存重新分析。重启中断会标记可恢复失败，下一次增量任务复用完整成功单元。
- 资料在分析期间变化时该单元失败，避免将变更前后内容当作同一版本。扫描不是仓库事务锁。
- 失败、超时、取消不替换当前快照。没有网络连接时本地单元不依赖外部模型；Git同步失败需恢复网络后重试。
- 人工修改仅在资料未变时保留；变更资料对应的人工修订列入待复核清单，旧版本继续可查。
- 「复用未变模型的已确认评审」默认关闭，显式勾选后仅对资料和完整模型定义均未变的节点／关系复用，并记录来源快照。
- 派生修订独立复制证据及源映射；删除原分析任务不会破坏该修订。发布基线所依赖的任务禁止直接删除。

## 静态提取与交互边界

MI／MM适配Java／Spring REST／JPA显式声明。未声明表名、列名和必填语义保持未知；不假定数据库命名策略。DTO返回结构没有在MI中完整递归展开，MyBatis XML、存储过程和运行时动态映射不在本次自动恢复范围。框架权限注解仅作声明，不等于权限执行证明。

多资料同名检测按模型类型与规范化名称分组，属于差异核对提示，不是语义等价判定；可结合已有AI分析再人工裁定。关系探索遍历已记录关联，不证明运行时传递影响。超过600节点使用静态初始布局，保留拖拽缩放，避免大图持续力导向运算。

文档上传每次1–10份，单份2MB、合计8MB；支持Markdown、TXT、HTML、DOCX，不支持旧版DOC、PDF及OCR。每项目最多20个资料单元。模型调用继续使用原配置和授权流程，本地增量分析本身不调用外部模型。

## API与Agent

工作台路径前缀：`/api/projects/:id/workbench`。

| 方法／后缀 | 功能 |
|---|---|
| GET 空后缀 | 资料、任务、校验、单元与记录 |
| POST `/materials`、`/upload` | 加入本地目录／Base64文档 |
| POST `/analyze` | 增量分析，可选`reuseReviews:true` |
| PUT `/edit` | `expectedSnapshot`、`id`、`changes`或批量`edits`；新建附`create`、`model`和可选`evidenceFrom` |
| GET `/validate`、`/impact`、`/conflicts` | 校验、邻域和同名提示 |
| POST `/model-status`、`/resolve-conflict` | 完整性依据／差异处理结论 |
| POST `/submit` | 提交当前快照 |
| POST `/baselines/:id/publish` | 门禁通过后冻结确认版本 |
| GET `/baselines/:id/export` | 已发布完整模型 |
| POST `/baselines/:id/context` | 已发布版本的编码上下文 |
| POST `/feedback` | 提交固定`snapshot`和`modelIds`的反馈；含`summary`、`files`、`tests`、可选`suggestions` |
| POST `/feedback/:id/accept\|reject\|apply` | 填写`reason`核验／驳回／应用修订建议 |

取消继续使用`POST /api/jobs/:id/cancel`。现有Agent查询与上下文接口支持`?baseline=<已发布ID>`；不同项目基线及不匹配快照会拒绝。上下文包含发布版本、差异裁定与反馈约定。技能CLI增加`baselines`、`--baseline`、`feedback --file ... --snapshot ...`，不自动修改用户源码或向外部Agent发起真实调用。

## 存储、升级与验证

SQLite新增`materials`、`work_units`、`records`表，`jobs`新增任务类型和选项列；历史任务默认原队列。上传资料存于`.runtime/uploads`，新修订及独立证据存于`.runtime/revisions`。完整备份应停止服务后复制整个数据目录；仅备份SQLite不足以恢复模型证据。数据目录含模型凭据配置，不作为源码包共享。

本轮自动化回归57项全部通过；新增验证覆盖混合资料与MI/MM、上传隔离、失败恢复、失效目录、取消、重启检查点、损坏缓存、并发旧修订拒绝、证据保留、引用更新、显式评审复用、基线发布门禁、冻结上下文、差异裁定及反馈草稿。临时测试项目还经过真实浏览器操作验证，覆盖编辑、校验、关系探索、基线入口、反馈与上传，无页面脚本错误。

测试中的发布和确认只针对临时测试数据；未替用户审批真实项目，也未执行外部模型或OpenCode真实联调。

首次从旧单资料快照迁移时，来源哈希在新源码中仍可核验的AI／人工补充草稿会保留并重建命名空间引用；不迁移批准状态。当前文档解析器也支持Rule、Role、Owned aggregates、Event、Interface等英文显式表头，保留文档声明和源码事实的区别。
