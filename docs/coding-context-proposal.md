# 任务 3：编码上下文包实现方案（待决策）

历史方案。当前已实现手工上下文导出、项目 Skill 接入脚本及只读 HTTP 查询工具；未实现 MCP 和 ZIP 打包。最新使用方式见 coding-context-usage.md。

## 建议决策

先实现“用户选择范围、可预览、版本固定的 Markdown + JSON 上下文包”。复用当前 SQLite、模型快照、图谱关联、质量诊断及差异报告，保持 All-in-one 架构。以一个真实支付需求作为试点，确认 Agent 能正确引用证据后，再扩展只读 MCP。

## 用户流程

1. 选择项目和快照，填写需求说明。
2. 搜索并选择业务对象、行为或流程；选中节点是一等输入，需求文本只辅助检索，避免中文模糊匹配自动决定全部范围。
3. 默认扩展一层已有关系；用户可选择二层和关系类型。预览节点、证据文件、质量提示和预计大小。
4. 用户可排除无关节点、选择原始提取或人工修订口径，并确认待评审内容的处理方式。
5. 下载包含 Markdown、JSON 和版本清单的包，交给编码 Agent。可额外下载建议的项目指令片段与 Skill 模板，经用户审阅后放入代码仓库。
6. Agent 交付时列出引用的快照、模型 ID、变更范围和测试结果。需求改变业务规则时同步提出模型修订。

## 输出内容

| 文件 | 内容 |
|---|---|
| README.md | 需求、范围、版本、使用方法、限制与质量状态 |
| coding-context.md | 相关对象/行为/规则/流程/查询、源码锚点、待确认问题、基于分支的测试检查项 |
| models.json | 所选模型和真实图边，保留来源与人工修订标记 |
| manifest.json | 项目、快照、Git 版本/输入指纹、模型 ID、文件哈希、筛选参数、生成时间、截断情况 |
| agent-instructions.md | 建议追加到项目 AGENTS.md 的简短规则片段；不覆盖原项目指令 |
| skill-template/SKILL.md | ontology-context-init 工作流模板；标为可选安装产物 |

首版默认输出源码位置与哈希；源码原文或片段作为显式选择项，不默认打包整个仓库、配置文件、密钥或业务数据库内容。打包可复用 Python 标准库 zipfile，无须新增基础组件。

## 内容选择与可信度

- 通过节点 ID 和已有图边扩展，不能把二层可达关系补造成直接业务依赖。
- 确认语义、待评审映射、仅响应契约分别标记；不能把静态检查通过转换为“业务规则已确认”。
- “只含已确认模型”应在包中明确列出被排除的待评审边界，不能展示成完整业务范围。
- 从选定快照读取源码证据，不能混用当前工作区源码。旧导入快照没有隔离源码时，显示限制并校验哈希。
- 固定生成开始时的快照和修订记录；导出中若快照已删除则失败，不自动切换到其他版本。
- 设置节点、关系、文件、片段和文本预算；超过限额时提示用户缩小范围，并列出截断内容，不能静默丢弃约束。
- 测试建议由已有分支、参数与规则形成检查项，不生成未经确认的业务数值或验收事实。

## 三种实现选项

| 选项 | 开发范围与依赖 | 优点 | 局限 |
|---|---|---|---|
| A：可预览上下文包（推荐首版） | 范围选择、确定性提取、MD/JSON/清单导出、指令/Skill 模板 | 容易验证；兼容不同编码 Agent；无外部模型依赖 | 用户需要选择范围并交给 Agent；包生成后不会自动跟随新快照 |
| B：本地只读 MCP | 在 A 的选择服务上增加 search_models/get_model/get_neighbors/get_coding_context/get_source_evidence | 编码时按需查询，减少反复导出 | 需要配置 Agent 连接和调用规则；依然需要明确项目/快照、限制返回体积与记录引用 |
| C：自然语言自动规划/自动写代码 | 再接外部模型、提示词、执行与验收机制 | 可进一步降低人工整理成本 | 引入新的推断、成本和可验证性问题；需要单独设计与评估 |

Skill 说明如何使用知识，AGENTS.md 提供项目入口，模型包/MCP 提供事实。全局记忆只保留跨项目通用原则，不作为某个银行项目的业务规则库。

## 首版验收

- 同一范围和快照生成相同的模型/证据集合，清单可追溯。
- 新增、删除、待评审关系及未支持内容在预览和下载中一致。
- 包内不存在越界源码路径和其他项目数据；未选择源码时不包含源码原文。
- 编码 Agent 能说明引用了哪些模型和快照，并定位至对应源码。
- 用人工影响分析作为参照，核对相关文件、规则与测试场景的遗漏；不以包大小或节点数量代替效果。

## 需要用户决定的范围

1. 首版选择 A，还是同时建设 B？建议先 A。
2. 默认包含原始模型还是当前人工修订结果？建议当前修订结果并附原始证据及修订标记。
3. 是否允许导出源码片段？建议默认关闭、按次显式勾选。
4. 首个试点选支付退汇、贷款还款，还是 EPS 支付审批？建议选已有真实需求、领域人员能确认规则的一项。
