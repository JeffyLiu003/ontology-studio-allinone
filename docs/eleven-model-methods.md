# 七 / 十一模型项目建模管理

本功能属于 `ontology-studio-allinone`，入口为 http://127.0.0.1:45991/#/overview 。合同示例的5001服务已停止；其此前改动保留，不作为本平台实现。

## 规范与方法

参考 https://github.com/sharptoolbox/ontology_modeling_framework/blob/main/ontology_modeling_framework_v6.md 。

七模型沿用M1对象、M2行为、M3规则、M5主体、M6流程、M7查询和MU界面。十一模型在此基础上增加ME事件、M4事件协同场景，并提供MM数据映射、MI接口两个配套模型，因此有11份模型产物。M4不替代M6人工任务与审批。

## 后端

- SQLite projects新增 `modeling_method`，仅允许seven/eleven，旧nine兼容迁移；启动时将旧记录默认归为seven，原模型快照文件和评审不重写。
- 项目身份与建模方法绑定；相同资料路径在两种方法下分别接入，方法内重复接入仍幂等。已有项目不原地切换方法。
- bootstrap、任务列表按方法过滤；指定method的项目请求校验归属，跨项目快照仍拒绝读取。方法属于建模隔离，不是多租户安全权限体系。
- 分析任务固定项目方法，传递给文档解析器；快照统一写入方法、规范版本、额外模型与能力边界。七模型项目不创建额外四份产物。
- 十一模型文档解析支持明确的事件、事件场景、映射和接口声明及表格，保存文档证据；任意自然语言仍需可选AI分析与评审。
- AI分析协议、候选校验及候选应用按项目方法选择允许的模型类型；复用原密钥配置、证据逐字校验和确认流程。本次开发验证未发送真实模型请求。
- 新增模型复用原有节点、快照、评审、编辑和导出链路；ME输出eventId/eventName，M4集合为event_scenarios，MI输出interfaceId。

## 前台

左侧顶部选择建模方法；项目切换列表、任务和接入表单随方法变化。所选方法和项目在浏览器中分别记忆，切换清理旧图谱、检查器及助手上下文。异步加载通过代次检查避免旧方法数据覆盖新方法。

十一模型工作台增加ME/M4/MM/MI模型卡片、筛选、属性查看和导出，复用现有图谱与评审界面；语义投影识别新增模型类别。没有识别出的模型保持空集合，不生成虚假的已实现能力。

## 能力边界

本增量不是完整v6语义验证器。源码静态适配器继续提取已有七模型信息，但暂不自动确认源码中的事件投递、场景执行与对象数据表映射；十一模型新增部分可通过明确文档声明或有证据的AI候选补充。不会将同步调用自动转换为事件协同。模型齐备、任务完成、证据存在与业务确认是不同状态。

原有流程图和查询能力继续复用。正式的事件链执行、事件消费幂等、完整跨模型引用约束、模型驱动生成应用仍需后续实现。项目方法通过新建项目选择，修改既有节点仍复用名称/描述修订，不提供任意YAML全文编辑器。
